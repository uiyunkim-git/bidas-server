How to Upload

For data contributors depositing sequencing runs into the repository. Just fetching data? See How to Download.

Uploading requires the repository's administrator credentials. If you are depositing data you will already have been given them; if not, contact KAIST-BISL. Read-only accounts cannot write — they fail with AccessDenied the moment they try.
This account can do everything. It can delete any object in any bucket, and there is no undo. Read Overwriting and deleting before you run anything with --remove or rm in it, and do not paste the password into a script — mint an access key for that instead.

Do not use the browser for large uploads. A dropped connection restarts the whole transfer, and browsers handle multi-hour uploads of multi-gigabyte files badly. Use mc mirror, which resumes.

1. In your web browser

Open the MinIO console and sign in with the administrator account.

  1. Pick a bucket, or press Create Bucket.
  2. Navigate into the prefix you want, or press Create new path to make one.
  3. Press Upload and choose files, or drag them onto the file list. Upload Folder keeps the directory structure.

Progress shows in the bottom-right. Leave the tab open until it finishes.

How to organise what you upload

The repository follows one bucket per collection, one prefix per assay and brain region:

LevelExample
Bucket — the collectionneuropathology-consortium
Prefix — assayrna-seq/
Prefix — brain regionrna-seq/hippocampus/
Objectsrna-seq/hippocampus/S042_R1.fastq.gz

A few things worth getting right the first time, because renaming objects in S3 means copying them again:

  • Lower case, hyphens rather than spaces or underscores in bucket and prefix names. Bucket names must be 3–63 characters, and may not contain underscores or upper case at all.
  • Keep the sample identifier at the start of the file name, so a plain alphabetical listing groups a sample's files together.
  • Upload a MANIFEST next to the data — sample ID, file name, size, checksum, read length, library prep. Nothing else records it.
  • Do not create a placeholder object just to make a folder appear. S3 has no directories; a prefix exists exactly as long as an object uses it.

Overwriting and deleting

This account can overwrite and delete anything, and there is no undo — versioning is off. mc mirror without flags never deletes, which is the safe default. Two flags change that, so know what they do before typing them:

Enable versioning on a bucket if you want deletions to be recoverable — in the console under the bucket's settings, or mc version enable bidas/<bucket>. Do it before the first upload; it does not apply retroactively.

Troubleshooting

AccessDenied on upload, but downloads work
You are signed in with a read-only account. Uploading needs the administrator account, or a key scoped to the bidas-upload policy.
SignatureDoesNotMatch
Nearly always a clock problem — S3 signatures expire. Check your machine's time (timedatectl, or turn on NTP). Otherwise the secret key is mistyped.
Transfer dies part-way through a large file
Re-run the same mc mirror command. It picks up what is missing. If it dies repeatedly at the same point, lower the concurrency: mc mirror --limit-upload 100MiB ….
Interrupted uploads taking up space
Abandoned multipart uploads linger. List them with mc ls --incomplete bidas/<bucket>/ and clear them with mc rm --incomplete --recursive --force bidas/<bucket>/.
InvalidBucketName
No upper case, no underscores, 3–63 characters.
