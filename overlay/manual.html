How to Download

For researchers who have been granted access to the repository. Depositing data instead? See How to Upload.

The repository stores its data in MinIO, an S3-compatible object store. Sign in to the MinIO console to browse and download in your web browser, or point any S3 client at it — the MinIO client mc, the AWS CLI, boto3, Cyberduck, rclone.

All data in this repository is private. Every bucket requires credentials; there are no public download links. Only this website itself is open.

What you need

  • The username and password issued to you by KAIST-BISL. The same pair works for the console login and for every command-line client below, where it is called an access key and secret key.
  • Download accounts are issued per request — contact KAIST-BISL. Such an account can list and fetch anything in the repository, but cannot upload, overwrite or delete. Depositing data is a different account; see How to Upload.
  • Enough disk space. Whole-cohort RNA-Seq runs are large; check sizes in the console before you start.

1. In your web browser

The simplest option, and nothing to install. Open the repository — Sign In to Repository in the menu on the left — and sign in with your username and password. You get a proper file browser: buckets down the side, folders and objects in the middle, click a file to download it. Text files and PDFs preview in place, several objects can be downloaded together, and Access Keys is where you mint the key pairs the tools below want.

Sharing a file with a colleague

Open an object in the console and choose Share. The link it gives you carries its own signature and expires on a deadline you pick, so the recipient needs no account. The same thing from the command line:

2. mc — the MinIO client

The best tool for bulk transfers: it resumes, mirrors and parallelises. Download a single static binary from min.io.

Install

# Linux
curl -O https://dl.min.io/client/mc/release/linux-amd64/mc
chmod +x mc && sudo mv mc /usr/local/bin/

# macOS
brew install minio/stable/mc

# Windows (PowerShell)
Invoke-WebRequest -Uri https://dl.min.io/client/mc/release/windows-amd64/mc.exe -OutFile mc.exe

Register this repository

—

The alias bidas is stored in ~/.mc/config.json. Do this once.

Browse

mc ls bidas                                    # buckets you can see
mc ls bidas/neuropathology-consortium          # top level of one bucket
mc ls --recursive bidas/neuropathology-consortium/rna-seq/hippocampus/
mc du bidas/array-collection                   # how big is it

Download

# one file
mc cp bidas/public/examples/Cytokine.tsv .

# a whole prefix, in parallel
mc cp --recursive bidas/neuropathology-consortium/rna-seq/hippocampus/ ./hippocampus/

# keep a local copy in sync - re-run it after an interrupted transfer,
# only what is missing or changed is fetched
mc mirror bidas/array-collection/rna-seq/ ./array-collection/

mc mirror is the one to use for large transfers: it is restartable, so a dropped connection costs you nothing.

Verify

mc stat bidas/public/examples/Cytokine.tsv      # size, etag, content type
mc cat bidas/public/README.md

Share a time-limited link

mc share download --expire 168h bidas/neuropathology-consortium/rna-seq/hippocampus/sample.bam

Troubleshooting

SignatureDoesNotMatch
Almost always a clock problem — S3 signatures expire. Check that your machine’s time is correct (timedatectl, or enable NTP). Failing that, the secret key was mistyped.
AccessDenied
Your key is valid but has no rights to that bucket. The read-only account can list and download; it cannot write. Contact KAIST-BISL if you need more.
NoSuchBucket / empty listing
Check the bucket name against the table above, and make sure your client uses path-style addressing. mc and the AWS CLI do this automatically against a custom endpoint; some SDKs need force_path_style=True.
Transfer keeps dying on a large file
Use mc mirror instead of mc cp and just re-run it.
